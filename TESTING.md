# Перевірки

## Локальна інтеграція — 6 листопада 2026 року

Тест запущено на Windows із Python 3.12 та ізольованим PostgreSQL 16.15, завантаженим як ZIP і перевіреним за SHA-256. PostgreSQL слухав лише `127.0.0.1:55432`; API, воркер і мок хелпдеску були окремими локальними процесами. Зовнішній API-ключ LLM не використовувався: воркер виконав реальні HTTP-запити до провайдера, отримав `401` і застосував статичну відповідь із тестовою затримкою 5 секунд.

`python tests/integration.py` пройшов чотири сценарії:

1. 12 одночасних копій одного вебхука повернули `202` менш ніж за 2 секунди, з'явилася одна чернетка, після схвалення мок зберіг одну відповідь.
2. Мок записав відповідь до таймауту HTTP-клієнта; повторне відправлення зі сталим `Idempotency-Key` лишило один запис і перевело звернення в `sent`.
3. Після тимчасового `5xx` воркер повторив відправлення й завершив його після відновлення мока.
4. Відхилена чернетка перейшла в `rejected` і не потрапила до мока.

Перший запуск тесту виявив помилку тестового клієнта: він надсилав форму схвалення як JSON. Запит виправлено на `application/x-www-form-urlencoded`, після чого всі чотири сценарії пройшли. Тимчасові процеси зупинено; тестові порти більше не слухають.

## Що лишається перевірити

- Docker Compose не запущений у цьому середовищі; на VPS Docker за рішенням власника не встановлюється.
- GitHub Actions не виконав жодного кроку через блокування акаунта GitHub, пов'язане з оплатою. Це не результат тестів застосунку.
- Реальний API хелпдеску відсутній. Гарантія від дублювання доведена для мока, який підтримує ідемпотентний ключ; у реального API цю підтримку потрібно перевірити окремо.
- Тест не моделював повний пік 500 звернень за 10 хвилин.
